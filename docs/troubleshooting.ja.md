# トラブルシューティング

<p align="center" style="margin-top:1.25rem"><a href="./troubleshooting.kr.md">한국어</a> | <a href="./troubleshooting.en.md">English</a> | <strong>日本語</strong></p>

## 保存できない

以下の項目を確認します。

- Machbaseの`Host`、`Port`、`API Token`
- APIトークンの検証結果が`✓`になっているか（後述の「トークンの検証に失敗する」を参照）
- 追加したモデルの`Display Name`、`Model ID`
- 実際に使用できるプロバイダーが1つ以上登録されているか

入力が欠けていると、保存時にエラーメッセージが表示されます。

## トークンの検証に失敗する

| 結果の表示 | 原因 | 対処 |
| :--- | :--- | :--- |
| `✗ 유효하지 않은 토큰입니다`（無効なトークン） | トークンのコピーを誤ったか、Neoで削除・期限切れになったトークン | トークンをコピーし直すか、Neoコンソールで新しく発行 |
| `✗ 콘솔 로그인 계정(…)과 다른 계정(…)의 토큰입니다`（別アカウントのトークン） | コンソールにログインしているアカウントとトークンのアカウントが異なる | コンソールのログインアカウントのトークンを入力するか、そのトークンのアカウントでコンソールに再ログイン |
| `✗ Neo 콘솔 로그인 정보를 확인할 수 없습니다`（コンソールのログイン情報を確認できない） | コンソールにログインしていない | コンソールにログインした後、LLM Chatを開き直す |
| `✗ 검증 실패: …`（検証失敗） | LLM Chatサービスに接続できない | パッケージサービスが実行中か確認 |

## アプリを開くと「저장된 API 토큰을 사용할 수 없습니다」（保存されたAPIトークンを使用できません）が表示される

- ブラウザに保存しておいたトークンが、Neoで削除されたか期限切れになった場合です。
- Settings画面で新しいトークンを入力し、**검증**（検証）した後に**Save**を押します。

## チャットに「API 토큰이 확인되지 않았습니다」（APIトークンが確認されていません）が表示される

- 使用中にトークンが削除されたか、期限切れになった場合です。
- Settings画面で新しいトークンを入力して検証・保存した後、もう一度質問します。

## 別のPCやブラウザでトークンの再入力を求められる

- 正常な動作です。トークンはブラウザごと、コンソールアカウントごとに保存されます。
- 同じアカウントのトークンを入力して検証すると、サーバーに保存されている既存の設定（プロバイダー、モデル）が読み込まれます。
- 接続先のアドレスが変わっても（`127.0.0.1` ↔ `192.168.x.x`）、ブラウザは別のストレージとして扱うため、再入力が必要です。

## レポートのリンクが開かない

- チャット画面のレポートリンクは、保存されたAPIトークンでファイルを取得し、新しいウィンドウに表示します。
- 「API 토큰이 유효하지 않습니다」（APIトークンが無効です）と表示された場合は、Settingsでトークンを確認します。
- リンクのアドレスをコピーしてブラウザのアドレスバーで直接開くと、Neoがトークン認証を要求するため開けません（`401`）。チャット画面のリンクをクリックして開きます。

## タイマーの作成を依頼したのに登録されない

- LLM Chatは、タイマーの登録・開始・停止・削除・一覧照会をサポートしていません。
- タイマーに関する質問には、マニュアルに基づいて登録方法（WebコンソールのTimerメニュー、シェルの`timer`コマンド）とTQLの例を案内します。
- タイマーの登録と管理は、Neo WebコンソールのTimerメニューまたはシェルから直接行います。

## モデル一覧が空になっている

- このアカウントの設定をまだ保存していない場合、一覧は空になります。SettingsでSaveを押します。
- Settingsで実際にモデルを追加したか確認します。
- 該当するプロバイダーのAPI KeyまたはOllama URLが正しいか確認します。
- Chat画面でモデル一覧をもう一度開いて更新します。

## Chat画面がDisconnected状態になっている

- サーバーとの接続が一時的に切れた可能性があります。
- `Reconnect`ボタンで再接続します。
- 失敗が続く場合は、パッケージサービスの状態とブラウザのネットワーク状態をあわせて確認します。

## 質問を送ったのに応答が遅い

考えられる原因：

- 選択したモデル自体が遅い場合
- 外部プロバイダーの応答が遅い場合
- Machbaseのクエリやダッシュボード作成の処理に時間がかかる場合

この場合は、しばらく待つか、必要に応じて**Stop**で中断してから、質問をより簡単な内容に変えてもう一度試します。

## 期待した回答が得られない

- テーブル名を正確に入れて質問します。
- 期間、タグ、カラム名を一緒に書くと、結果がより安定します。
- 「dashboard」、「report」、「tag list」のように目的を明確に書くとよいでしょう。
- ローカルモデル（Ollama）は、1つの質問でSQLを8回まで実行します。多くの照会が必要な質問は分けて尋ねます。

## ダッシュボードの修正を依頼したのに新しいダッシュボードが作成された

- 現在のバージョンは、会話で既存のダッシュボードを修正する機能（チャートの追加・削除、期間の変更など）に対応していません。
- ダッシュボードの修正は、Neo Webコンソールのダッシュボード画面で行います。

## 時刻が想定と異なって表示される

- 照会結果・チャート・レポートの時刻は、ブラウザのタイムゾーンが基準です。
- 別のタイムゾーンが必要な場合は、質問に「in UTC」のように書きます。
- 質問中の日付（「yesterday」、「March 2025」）は、Neoサーバーのタイムゾーンで解釈します。ブラウザとサーバーのタイムゾーンが異なると、期間の境界がずれることがあります。

## 運用上の推奨事項

- 最初はプロバイダー1つ、モデル1つだけを登録して動作を確認します。
- Machbaseの接続情報が変わったり、トークンを新しく発行したりした場合は、Settingsですぐに修正します。
- 複数のモデルを使う場合は、Display Nameを区別しやすいように整理します。
