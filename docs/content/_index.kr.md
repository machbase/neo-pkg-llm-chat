Machbase Neo LLM Chat 패키지는 Machbase Neo 시계열 데이터베이스와 자연어로 상호작용할 수 있는 LLM 채팅 인터페이스입니다.
대화를 통해 데이터 조회, 대시보드 생성, 분석 리포트 작성, 메뉴얼 문서 탐색이 가능합니다.

패키지는 내부적으로 에이전틱 루프를 실행하여 사용자 질문을 LLM에 전달하고, 도구 호출을 Machbase Neo에서 실행한 뒤, 결과를 다시 LLM에 피드백하는 과정을 최종 응답이 생성될 때까지 반복합니다.

## 설치

Machbase Neo 좌측 사이드 패널에는 사용 가능한 패키지 목록이 표시됩니다.  
여기서 LLM Chat 패키지를 선택하고 `Install` 버튼을 누르면 설치할 수 있습니다.

설치에는 약간의 시간이 걸릴 수 있으므로, 완료될 때까지 잠시 기다립니다.

![패키지 설치 화면](/images/package-install.png)

### 요구 사항

- Machbase Neo 8.7.3 이상
- LLM Chat을 사용할 계정의 Machbase Neo API 토큰 (Neo 웹 콘솔에서 발급, [첫 설정]({{< relref "first-setup" >}}) 참고)

### 제거

좌측 패널에서 `neo-pkg-llm-chat`을 선택하고 **Uninstall**을 누르면 패키지와 관련 서비스가 제거됩니다.

## LLM 프로바이더

4가지 LLM 프로바이더를 지원합니다. 프로바이더 호출 자체는 단발(non-streaming) 요청·응답으로 처리되며, 도구 실행 단계별 진행 상황은 WebSocket을 통해 브라우저로 스트리밍되어 표시됩니다.

| 프로바이더 | API | 로컬 |
| :--- | :--- | :---: |
| Claude | Anthropic API | 아니오 |
| ChatGPT | OpenAI API | 아니오 |
| Gemini | Google Gemini API | 아니오 |
| Ollama | Ollama REST API | 예 |

프로바이더와 연결 설정은 웹 기반 Settings 화면에서 구성합니다. API Key, 모델 목록, Machbase Neo 연결 정보는 계정별로 서버에 저장되고, Machbase Neo API 토큰은 서버에 저장되지 않고 브라우저에만 저장됩니다.

## 에이전틱 루프

에이전틱 루프는 이 패키지의 핵심 실행 엔진입니다. 사용자가 질문을 보내면 시스템이 먼저 질문 유형을 감지하고, 이후 LLM이 도구를 선택하고 실행하는 자율 루프에 진입합니다.

### 질문 유형 감지

질문은 아래 순서로 판정해 실행 흐름을 고릅니다. 흐름마다 모델이 쓸 수 있는 도구가 정해져 있습니다([기술 참고]({{< relref "technical-reference" >}})의 공통 규칙 참고).

| 질문 | 흐름 |
| :--- | :--- |
| 코드(`SQL(`, `CHART(` 등)를 붙여 넣음 | 데이터 조회 |
| "리포트", "보고서", "report"가 들어감 | 리포트 — HTML 분석 리포트 생성 |
| "타이머", "timer", "cron", "스케줄러"가 들어감 | 문서 검색 — 매뉴얼로 안내(타이머 등록은 지원하지 않음) |
| 서버 버전·상태를 짧게 물음 | 시스템 정보 |
| "예측", "forecast" (리포트·대시보드 언급 없음) | 데이터 조회 — 예측 리포트 생성 |
| 실행 요청, 테이블·태그를 지목한 조회, "온도 몇 도야" 같은 측정값 질문 | 데이터 조회 |
| "뭐야", "어떻게", "예제", "사용법" 같은 개념·사용법 질문 | 문서 검색 |
| "심층", "고급", "FFT", "RMS", "스펙트럼", "이상 탐지" 등 | 고급 분석 — 분석 의도(IR)로 컴파일한 심층 차트 |
| 차트·대시보드·분석·추세 요청 | 기본 분석 — 테이블 기반 차트 |
| "평균", "최근", "몇 건", "목록" 같은 조회 표현 | 데이터 조회 |
| 인사 | 일반 대화 |
| 그 외 | 문서 검색 |

### 보정(Fixer) 레이어

도구가 실행되기 전에, Fixer 레이어가 LLM의 일반적인 실수를 자동 보정하여 호출이 성공하도록 만듭니다.

| Fixer | 설명 |
| :--- | :--- |
| 인자 정규화 | 도구 호출의 잘못되거나 오타난 파라미터명을 수정 |
| 탐색 보조 | `list_table_tags`의 테이블명을 추론하고, 기본 분석의 `describe_table`에 `profile`을 붙임 |
| 질문 정보 주입 | 리포트·차트 컴파일 도구에 질문에서 읽은 기간·단위·원문을 넣음(모델이 넣은 값보다 우선) |
| 시간 범위 보정 | `time_start` / `time_end`를 실제 데이터 범위에 맞게 조정 |
| 시간 값 정리 | `time_start` / `time_end`를 epoch ms 문자열로 맞춤 |
| 차트 정의 정리 | 대시보드 `charts` 배열을 정규화 |
| 줄바꿈 정리 | 글자 그대로 들어온 `\n`을 실제 줄바꿈으로 바꿈 |

### 가드 파이프라인

가드 파이프라인은 에이전틱 루프 주변에서 동작 가드를 실행합니다. pre-tool 가드는 도구 실행 전에, post-loop 가드는 모델이 종료하려 할 때 동작합니다.

pre-tool 가드:

| 가드 | 설명 |
| :--- | :--- |
| `consecutive_failure` | 같은 도구가 연속 실패하면 오류를 다시 읽고 고치도록 재유도하고, 컴파일이 4회 연속 실패하면 그 차트를 건너뛰게 함 |
| `dashboard_early` | 모든 TQL 템플릿 저장 전 대시보드 생성을 방지(고급 모드) |
| `redundant_finalize` | 대시보드 URL 발급(=완성) 후의 추가 마무리 호출을 차단(고아 파일 방지) |

post-loop 가드:

| 가드 | 설명 |
| :--- | :--- |
| `dashboard_omission` | 도구를 하나도 안 부르고 "대시보드 생성했다"는 거짓 완료 보고를 차단 |
| `chart_omission` | 고급 분석이 끝났는데 대시보드에 차트가 빠졌을 때 재촉 |
| `report_omission` | 리포트 모드인데 `save_html_report`가 호출되지 않았을 때 재촉 |
| `forecast_label` | 일반 분석 리포트를 만들어놓고 답변에서 "예측 리포트"라 부르는(검증·신뢰구간 없는 과거 분석을 예측으로 위장) 라벨을 교정 |
| `doc_index_answer` | 문서 도구 결과가 섹션 목록/탐색 안내뿐인데 본문 재조회 없이 답하려 하면 본문 조회를 강제 |
| `dashboard_answer` | 성공적으로 만든 대시보드 URL을 최종 답변이 빠뜨렸을 때 구제 |
| `tql_inject` (tql_omission) | 검증된 ```tql 차트가 최종 답변에 온전히 포함되도록 보장 |
| `raw_tql` | 도구 결과에 없는 = 손으로 쓴 ```tql을 탐지해 컴파일러로 재유도 |
| `fake_tql_answer` | 최종 답변의 지어낸/환각 TQL 문법을 차단 |
| `applied_basis` | 도구가 단위·기간·태그를 바꿨는데 답변에 그 값이 없으면 답변 끝에 `※ 적용 기준:` 한 줄을 붙임(로컬 모델) |

### 실행 단계 제한

도구를 실행하기 직전에 다음을 확인합니다.

| 제한 | 대상 | 동작 |
| :--- | :--- | :--- |
| 허용 도구 | 모든 모델 | 질문 흐름의 허용 목록에 없는 도구는 이름으로 불러도 실행하지 않음 |
| 같은 호출 반복 | 모든 모델 | 같은 도구를 같은 인자로 2번 실행한 뒤 또 부르면 차단 |
| SQL 실행 횟수 | 로컬 모델(Ollama) | 한 질문에서 `execute_sql_query`는 8번까지 실행하고, 이후에는 지금까지의 결과로 답하게 함 |
| 시간 단위 | 로컬 모델(Ollama) | "시간별·일별·주별·월별" 질문에 버킷이 없거나 다른 SQL이면 실행 전에 다시 쓰게 함. 예시 버킷식은 테이블에 ROLLUP이 있으면 `ROLLUP`, 없으면 `DATE_TRUNC` |

차단이 쌓이면 로컬 모델은 도구 사용을 멈추고 지금까지 확인한 내용으로 답합니다.

## 기본 작업 순서

1. Neo에서 LLM Chat 패키지를 설치합니다.
2. Neo 웹 콘솔에서 사용할 계정의 API 토큰을 발급합니다.
3. 처음 열면 Settings 화면에서 Host, Port, API 토큰을 입력하고 **검증**을 누릅니다.
4. 사용할 Provider의 API Key 또는 Endpoint를 입력합니다.
5. 사용할 Model을 한 개 이상 등록합니다.
6. Save 후 Chat 화면으로 이동합니다.
7. Chat 화면에서 모델을 선택하고 질문을 보냅니다.
