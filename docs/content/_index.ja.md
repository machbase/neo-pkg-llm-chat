Machbase Neo LLM Chatパッケージは、Machbase Neo時系列データベースと自然言語でやり取りできるLLMチャットインターフェースです。
会話を通じて、データの照会、ダッシュボードの作成、分析レポートの作成、マニュアル文書の探索ができます。

パッケージは内部でエージェンティックループを実行し、ユーザーの質問をLLMに渡し、ツール呼び出しをMachbase Neoで実行したうえで、その結果を再びLLMにフィードバックする処理を、最終応答が生成されるまで繰り返します。

## インストール

Machbase Neo左側のサイドパネルには、利用可能なパッケージの一覧が表示されます。  
ここでLLM Chatパッケージを選択し、`Install`ボタンを押すとインストールできます。

インストールには少し時間がかかる場合があるため、完了するまでしばらく待ちます。

![パッケージのインストール画面](/images/package-install.png)

### 要件

- Machbase Neo 8.7.3以上
- LLM Chatを使用するアカウントのMachbase Neo APIトークン（Neo Webコンソールで発行、[初期設定]({{< relref "first-setup" >}})を参照）

### アンインストール

左側のパネルで`neo-pkg-llm-chat`を選択し、**Uninstall**を押すと、パッケージと関連サービスが削除されます。

## LLMプロバイダー

4種類のLLMプロバイダーをサポートしています。プロバイダーの呼び出し自体は単発（non-streaming）のリクエスト・レスポンスとして処理され、ツール実行のステップごとの進行状況はWebSocketを通じてブラウザにストリーミング表示されます。

| プロバイダー | API | ローカル |
| :--- | :--- | :---: |
| Claude | Anthropic API | いいえ |
| ChatGPT | OpenAI API | いいえ |
| Gemini | Google Gemini API | いいえ |
| Ollama | Ollama REST API | はい |

プロバイダーと接続の設定は、WebベースのSettings画面で行います。API Key、モデル一覧、Machbase Neoの接続情報はアカウントごとにサーバーに保存されますが、Machbase Neo APIトークンはサーバーには保存されず、ブラウザにのみ保存されます。

## エージェンティックループ

エージェンティックループは、このパッケージの中核となる実行エンジンです。ユーザーが質問を送ると、システムはまず質問の種類を検出し、その後LLMがツールを選択して実行する自律ループに入ります。

### 質問タイプの検出

質問は次の順序で判定され、実行フローが選ばれます。フローごとにモデルが使えるツールが決まっています（[技術リファレンス]({{< relref "technical-reference" >}})の共通ルールを参照）。

| 質問 | フロー |
| :--- | :--- |
| コード（`SQL(`、`CHART(`など）を貼り付けた | データ照会 |
| 「리포트」、「보고서」、「report」を含む | レポート — HTML分析レポートを生成 |
| 「타이머」、「timer」、「cron」、「스케줄러」を含む | 文書検索 — マニュアルをもとに案内（タイマーの登録には非対応） |
| サーバーのバージョン・状態を短く尋ねる | システム情報 |
| 「예측」、「forecast」（レポート・ダッシュボードへの言及なし） | データ照会 — 予測レポートを生成 |
| 実行の依頼、テーブル・タグを指定した照会、「온도 몇 도야」（温度は何度？）のような測定値の質問 | データ照会 |
| 「뭐야」、「어떻게」、「예제」、「what is」、「how to」のような概念・使い方の質問 | 文書検索 |
| 「심층」、「고급」、「FFT」、「RMS」、「스펙트럼」、「이상 탐지」など | 詳細分析 — 分析意図（IR）からコンパイルした詳細チャート |
| チャート・ダッシュボード・分析・推移の依頼 | 基本分析 — テーブルベースのチャート |
| 「평균」、「최근」、「몇 건」、「목록」のような照会表現 | データ照会 |
| あいさつ | 一般会話 |
| その他 | 文書検索 |

> モード判定のキーワードは英語と韓国語のみ認識します。日本語で質問する場合も、レポートや詳細分析を依頼するときは`report`・`FFT`などの英語キーワードを含めてください。

### 補正（Fixer）レイヤー

ツールが実行される前に、FixerレイヤーがLLMのよくあるミスを自動的に補正し、呼び出しが成功するようにします。

| Fixer | 説明 |
| :--- | :--- |
| 引数の正規化 | ツール呼び出しの誤ったパラメーター名やタイプミスのあるパラメーター名を修正 |
| 探索の補助 | `list_table_tags`のテーブル名を推定し、基本分析の`describe_table`に`profile`を付ける |
| 質問情報の注入 | レポート・チャートのコンパイルツールに、質問から読み取った期間・単位・原文を渡す（モデルが入れた値より優先） |
| 時間範囲の補正 | `time_start` / `time_end`を実際のデータ範囲に合わせて調整 |
| 時刻値の整理 | `time_start` / `time_end`をepoch msの文字列にそろえる |
| チャート定義の整理 | ダッシュボードの`charts`配列を正規化 |
| 改行の整理 | 文字どおり入った`\n`を実際の改行に変換 |

### ガードパイプライン

ガードパイプラインは、エージェンティックループの周辺で動作ガードを実行します。pre-toolガードはツールの実行前に、post-loopガードはモデルが終了しようとするときに動作します。

pre-toolガード：

| ガード | 説明 |
| :--- | :--- |
| `consecutive_failure` | 同じツールが連続で失敗すると、エラーを読み直して修正するよう再誘導し、コンパイルが4回連続で失敗するとそのチャートをスキップさせる |
| `dashboard_early` | すべてのTQLテンプレートを保存する前のダッシュボード作成を防止（詳細分析モード） |
| `redundant_finalize` | ダッシュボードURLの発行（=完成）後の追加の仕上げ呼び出しをブロック（孤立ファイルの防止） |

post-loopガード：

| ガード | 説明 |
| :--- | :--- |
| `dashboard_omission` | ツールを1つも呼び出さずに「ダッシュボードを作成した」と偽って完了報告するのをブロック |
| `chart_omission` | 詳細分析が終わったのに、ダッシュボードにチャートが欠けているときに催促 |
| `report_omission` | レポートモードなのに`save_html_report`が呼び出されなかったときに催促 |
| `forecast_label` | 通常の分析レポートを作成しておきながら、回答で「予測レポート」と呼ぶ（検証・信頼区間のない過去の分析を予測と偽る）ラベルを修正 |
| `doc_index_answer` | ドキュメントツールの結果がセクション一覧/探索ガイドだけなのに、本文を再照会せずに回答しようとした場合、本文の照会を強制 |
| `dashboard_answer` | 正常に作成したダッシュボードURLが最終回答から抜けていた場合に救済 |
| `tql_inject`（tql_omission） | 検証済みの```tqlチャートが最終回答に完全な形で含まれるよう保証 |
| `raw_tql` | ツール結果にない=手書きの```tqlを検出し、コンパイラーへ誘導し直す |
| `fake_tql_answer` | 最終回答に含まれる捏造された/ハルシネーションによるTQL構文をブロック |
| `applied_basis` | ツールが単位・期間・タグを変更したのに回答にその値がない場合、回答の末尾に`※ 적용 기준:`（適用基準）の1行を付ける（ローカルモデル） |

### 実行段階の制限

ツールを実行する直前に、次の点を確認します。

| 制限 | 対象 | 動作 |
| :--- | :--- | :--- |
| 許可ツール | すべてのモデル | 質問フローの許可リストにないツールは、名前で呼び出しても実行しない |
| 同じ呼び出しの繰り返し | すべてのモデル | 同じツールを同じ引数で2回実行した後にさらに呼び出すとブロック |
| SQLの実行回数 | ローカルモデル（Ollama） | 1つの質問で`execute_sql_query`は8回まで実行し、それ以降はそれまでの結果で回答させる |
| 時間単位 | ローカルモデル（Ollama） | 「시간별・일별・주별・월별」（時間別・日別・週別・月別）の質問に対し、バケットがない、または異なるSQLは実行前に書き直させる。例示するバケット式は、テーブルにROLLUPがあれば`ROLLUP`、なければ`DATE_TRUNC` |

ブロックが重なると、ローカルモデルはツールの使用をやめ、それまでに確認した内容で回答します。

## 基本的な作業手順

1. NeoでLLM Chatパッケージをインストールします。
2. Neo Webコンソールで、使用するアカウントのAPIトークンを発行します。
3. 初めて開いたら、Settings画面でHost、Port、APIトークンを入力し、**검증**（検証）を押します。
4. 使用するプロバイダーのAPI KeyまたはEndpointを入力します。
5. 使用するモデルを1つ以上登録します。
6. Saveしてから、Chat画面に移動します。
7. Chat画面でモデルを選択し、質問を送信します。
